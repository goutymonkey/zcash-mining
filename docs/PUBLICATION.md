# Public repository preparation

This document records the preparation of the source repository for public
visibility. It does not authorize a manufacturing release or change GitHub
visibility. The source baseline reviewed was `768e530` (v0.5.0); the
preparation changes add licensing, attribution, contributor documentation,
CI and clearer statements of evidence availability.

## Snapshot split

This public snapshot removes the private production handoff package
(RFQs, sourcing requests, pricing/market-watch, SRAM-compiler
requests and process selections). Those materials are maintained
privately. The public repository will live under `github.com/goutymonkey/zcash-mining`;
security contact is GitHub private vulnerability reporting on that repository.

## Repository review

- Both GitHub branches (`main` and
  `cursor/bucket0-tracker-and-nh16-7d2c`) were fetched. The 16 commits reachable
  from those branches and the existing tags were scanned using Gitleaks
  8.30.1 with its default rules.
- Two `generic-api-key` findings were reviewed. Both were 64-character
  SHA-256 values for `memory_accesses.csv` in
  `asic/chip/production/verification_snapshot.json`, introduced in commits
  `f2397e7` and `11d708c`. The exception in `.gitleaks.toml` requires both
  that exact file and that exact metadata format. Other rules remain active.
- A repeat history scan with that exception found no credential matches.
- Tracked files and historical paths were checked for credential folders,
  private keys, wallet files and locally provisioned process data. None of
  those paths was tracked. Local ignored files are not part of this review
  or the publication payload.
- Commit metadata includes the original maintainer's Git author name and email.
  Historical engineering records retain some original local filesystem
  paths. Those records have not been rewritten or represented as portable
  artifact downloads.
- All 28 file hashes in the Plan D source manifest still match. Existing
  hardware, models, archived evidence and the TLA+ JAR are unchanged.
- A clean source export passed all 306 Python tests with Python 3.11 and
  NumPy 1.26.4, all 22 Zig tests, and the offline `(48,5)` demo. The GitHub
  Actions workflow passed actionlint 1.7.12. Scanner controls confirmed that
  the checksum exception does not exempt unrelated credentials or files.
- GitHub had no releases or Actions artifacts, and Discussions was disabled.
  The existing open pull request (#1) had no comments or reviews. Its
  autogenerated Cursor agent-session footer was removed; its engineering
  notes and branch history were preserved.

## Before changing visibility

1. Publish from a commit containing the licensing and preparation files.
   Existing release tags predate this license package; preserve those tags
   and use a new tag for a self-contained public source release.
2. Check the CI workflow on the intended commit. It tests the CPU software
   and verification tooling and scans fetched history; it does not qualify
   an ASIC, board or physical implementation.
3. Repeat the history scan if new commits, branches or tags are added, and
   review any newly added artifacts. A source-history scan does not cover
   GitHub issue attachments, release assets, Actions artifacts or private
   supplier files stored elsewhere.
4. Confirm that any GitHub-hosted discussions, issues, releases and artifacts
   intended to become visible can be shared. Keep production PDKs, SRAM
   compiler outputs and NDA material outside this repository.
5. When the owner chooses to make the repository public, enable GitHub
   private vulnerability reporting and available secret-scanning/push
   protection. [GitHub documents private reporting setup](https://docs.github.com/en/code-security/how-tos/report-and-fix-vulnerabilities/configure-vulnerability-reporting/configure-for-a-repository).
   The security contact is GitHub private vulnerability reporting on the
   public repository.

The project's public description and release notes should retain the
experimental status and distinguish recorded simulations and projections
from fabricated-silicon measurements. See [STATUS.md](STATUS.md).
